## Résumé de l'analyse

La page `/activities-beta/[id]` existe déjà avec une architecture fonctionnelle : route → ActivityBetaPage (orchestrateur) → sous-composants. Le travail demandé est **frontend uniquement**, sans modifier le backend.

Les problèmes identifiés dans `docs/modifications.txt` sont confirmés par la lecture du code :

1. **Largeur** : la page utilise `space-y-4` sans wrapper d'élargissement. Le `PageContainer` global donne `max-w-[88rem]` via le metadata `container: 'wide'`, mais la page beta ajoute des marges négatives dans la sub-nav qui supposent une largeur spécifique. Le contenu doit être poussé pour utiliser l'espace.

2. **Hero** : 
   - La date du jour (`new Date().toISOString()`) est affichée dans la barre "Retour" en haut de `ActivityBetaPage.tsx` au lieu de la vraie date d'activité.
   - Les badges (source, type) sont absents.
   - Le bouton "Exporter" est présent mais non fonctionnel.
   - Les KPI n'incluent pas FC max, puissance, cadence, GAP dans le hero.
   - Le bouton "Renommer" existe et fonctionne.

3. **Sous-navigation** : 
   - Ordre incorrect : `Aperçu → Analyse → Splits → Carte → Relief → Zones → Détails`
   - Ordre attendu : `Aperçu → Analyse → Carte → Splits → Zones → Relief → Détails`
   - Style différent de la cible (pas de `backdrop-blur`, pas de `bg-slate-50/90`, barre active différente)
   - Ancre "carte" dupliquée (dans `ActivityBetaPage.tsx` section et dans `ActivityMapCard` via `id="carte"`).

4. **Sections Splits/Zones** : actuellement dans une seule section `id="splits"` avec `grid grid-cols-12`. Doivent être deux sections séparées (splits 7/12, zones 5/12).

5. **Analyse principale** : utilise `ActivityCharts` complet → empilement vertical de 6 graphes. Trop long.

6. **Carte** : 
   - `colorMetric` est un état local mais n'est pas passé à `ActivityMap` (pas de prop `colorMetric`). Le sélecteur est décoratif.
   - Boutons recadrage et plein écran sans comportement réel.

7. **ZonesCard** : double système de tabs (un dans ZonesCard, un interne dans ZonesBreakdown). Redondant et confus.

8. **ReliefCard** : fusion altitude/pente par égalité flottante `(g.distance_km as number) === dist` → bug.

9. **ActivityAccordions** : chaque accordéon appelle `MetricsRegistryRenderer` avec `REAL_METRIC_SECTIONS` complet → affichage répété des mêmes métriques dans chaque section. Les sections ne filtrent pas.

## Décisions de cadrage

1. **Périmètre strict frontend** : toutes les modifications se limitent aux fichiers dans `frontend/src/components/activity-beta/` et `frontend/src/app/activities-beta/`. Pas de backend.

2. **Création de composants utilitaires** : `BetaCard`, `MetricTile`, `EmptyState`, `ToggleButton` (recommandés dans la spec) seront créés dans `ui/` pour éviter la duplication de code entre les cartes.

3. **Option A pour l'analyse principale** (graphe synchronisé compact) retenue car meilleure UX. Les graphes détaillés complets seront déplacés dans un accordéon "Courbes détaillées" sous Détails.

4. **Pas de nouveau hook ou endpoint** : toutes les données nécessaires sont déjà disponibles via les hooks existants.

5. **Préservation du composant `ActivityMap`** : ajout d'une prop optionnelle `colorMetric` à `ActivityMapProps` dans `ActivityMapCard`, sans casser l'utilisation dans `/activities/[id]`.

## Ambiguïtés rencontrées

- **Bouton "Exporter"** : le fichier demande de le masquer s'il ne fonctionne pas. En l'absence de certitude, on le masque.
- **Boutons recadrage et plein écran carte** : idem, masqués si non fonctionnels.
- **ZonesBreakdown** : difficile de savoir si la refonte du double tab système nécessite de modifier `ZonesBreakdown` ou de le wrapper. On opte pour un remplacement local du rendu dans `ZonesCard` (suppression de l'import de `ZonesBreakdown`, rendu inline avec stacked bar + table).
