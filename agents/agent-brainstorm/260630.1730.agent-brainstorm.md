### Constats clés

- `cardiac_drift_pct` est un doublon parfait de `decoupling_pct` — même valeur, jamais exposé par l'API.
- Aucune des 4 nouvelles tables n'existe. Les calculs (zones, splits, climbs) sont faits à chaque requête.
- `InMemoryCache` existe mais n'est pas utilisé par les endpoints d'analyse.
- `progress_activity_index` manque 8 colonnes pourtant calculées par `compute_garmin_like_stats()`.
- 3 index manquants identifiés.
- ~30 endpoints non documentés dans `metrics_catalog.md`.
- Le parsing FIT ne supporte pas les messages `lap`.

### Décisions de cadrage

- `cardiac_drift_pct` : supprimé du modèle ORM, colonne physique laissée si SQLite < 3.35.
- `METRICS_VERSION` : 6 → 7 pour forcer le recalcul complet.
- Zones : une ligne par zone par activité, `zone_type` pour le filtrage.
- Peuplement : UNIQUEMENT via indexation lente (pas d'impact sur le fast).
- Cache : TTL 60s, clé basée sur activity_id + HR max effectif.
- P4 : non implémenté.
- Extraction FIT laps : limitée au parsing, table optionnelle.
- Ordre : P1 → P2 → P3 → mise à jour base-sqlite.md.
