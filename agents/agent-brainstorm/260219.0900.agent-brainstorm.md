## Constat repo (points bloquants Docker/LAN)

- `frontend/next.config.ts` hardcode la rewrite `/api/*` vers `http://127.0.0.1:8000/*` (OK en local, KO en Docker car `127.0.0.1` pointe sur le conteneur).
- `frontend/.env.local` contient `NEXT_PUBLIC_API_URL=http://localhost:8000` (dangereux en prod: le navigateur d'un client LAN appelle SON localhost).
- Backend: persistance sous `COURSESCOPE_DATA_DIR` (default `./data`) + sqlite par defaut sous `data/coursescope.sqlite` si `COURSESCOPE_DATABASE_URL` non defini.
- Backend CORS limite a localhost/127.0.0.1 (OK si API non exposee et proxy Next, sinon il faut un override LAN).

## Strategie retenue

- 2 conteneurs: `api` (FastAPI) + `web` (Next.js).
- Exposer uniquement `web:3000` sur le LAN; ne pas publier `api:8000` par defaut.
- Faire passer toutes les requetes navigateur via le proxy Next (`/api/*` -> `http://api:8000/*`).
- Persister les donnees runtime via un volume (monte sur `/data` + `COURSESCOPE_DATA_DIR=/data`).
