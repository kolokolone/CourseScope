# 260219.0935 - agent-brainstorm log (image unique + run_linux.sh)

Demande (user): sur Windows, il lance `start_backend.bat` puis `start_frontend.bat`. Il veut que l'image Docker lance automatiquement backend + frontend, idealement en reutilisant `run_linux.sh` mais modifie en concordance, pour un deploiement ultra simple (image unique "immich-like").

## Etat actuel

- `run_linux.sh` est un launcher dev-only:
  - cree venv + installe deps
  - uvicorn `--reload --host 0.0.0.0`
  - `npm run dev`
- `frontend/next.config.ts` proxy `/api/*` -> `http://127.0.0.1:8000/*`.
  - Avec une image unique, ce hardcode est compatible (API et web dans le meme conteneur).
- Danger prod: `frontend/.env.local` definit `NEXT_PUBLIC_API_URL=http://localhost:8000`.
  - En prod LAN, le navigateur d'un client appelle SON localhost.

## Strategie proposee

- Garder Windows local (start_backend + start_frontend) inchanges.
- Modifier `run_linux.sh` pour ajouter un mode `--docker`.
- Construire une image unique via `Dockerfile` multi-stage:
  - build Next
  - runtime Node + Python + deps + `tini`
  - `CMD /app/run_linux.sh --docker`
- Retirer `frontend/.env.local` du repo et fournir un exemple.
- Deploiement Dockge: 1 seul service compose qui expose 3000 et monte `/data`.

## Modifs appliquees aux docs

- `agents/modifications.txt` mis a jour: image unique + run_linux.sh en entrypoint.
- `agents/agent-brainstorm/modifications.md` mis a jour pour rester aligne.

## Points d'attention

- CRLF Windows: un script bash avec CRLF peut casser en conteneur; le Dockerfile propose un `sed -i 's/\r$//'`.
- Signaux: `tini` en entrypoint pour arret propre.
